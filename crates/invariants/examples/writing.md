# Tidepool

Tidepool is a small backup tool for people who don't want to think about backups. It quietly watches the folders you care about and copies each change to a bucket you own. Tidepool is a backup tool for photos and documents. No setup. No config. You pick the folders and name the bucket on the first run. Tidepool never loses a file, and nothing leaves your laptop unencrypted. It's not just a copy of your files—it's peace of mind. In practice, the overall experience of managing backups becomes significantly smoother for everyone involved.

Here's where it gets interesting: Tidepool never stores a full copy of your files. Each change is split into chunks, and the chunks are deduplicated before they are uploaded. You run the first sync, and you choose the bucket region. The first sync is fast without being heavy on your laptop. You wait about 4 minutes for each 10 GB on a home connection. You don't see a progress bar during the first sync, so you check the log. The upload is not 100% efficient, but you still get each file back.

The shape of your data lives in a small index, and that index is the engine of the whole system. Each line of the index is one chunk. Each backup is two files: the chunk store, and an index file with the same name that holds the hashes and the folder paths. The index lists each chunk of a file, and the scheduler picks each changed folder. The scheduler decides which folder goes first. Keep the index file next to the chunk store. Do not delete the index file. Never run `tidepool purge` on your only copy.

This matters because restores are where most backup tools fall apart. With Tidepool, a restore isn't a special mode, it's just a sync in the other direction. The real issue isn't speed—it's trust. The restore follows the order of the index. The restore command then checks each hash and returns the missing chunks. Run `tidepool restore ~/photos` to copy a folder back from the bucket. You cannot restore more than 10 GB in one run. Deleted files do not count toward your quota. If you see `no index`, you deleted the index file; run `tidepool rebuild`. If you skip the bucket name, you see `no bucket` on the first run. Unless you set a schedule, you start each sync by hand. A 404 means the bucket does not exist in this region. The old docs said you need an account, but you do not need one. You need a second key for buckets over 1 TB, not just the owner key. Duplicate chunks are removed on your laptop, not in the bucket. Tidepool does not read iCloud folders yet, so copy them to a local folder first. Your old backups are not on your laptop but in the bucket, so you have no problem with disk space. It's not a bug — it's a design choice.

A backup is complete when it holds each chunk of each folder. A backup is complete when you see `done` for each folder. The restore is pretty fast, but it is not instant. I don't think you need a GUI for this. The restore speed did not disappoint. The app is light and quiet without feeling empty. The point is simple: your backups should hold up when you need them, and they should stay yours.
